# 최종 품질 검증·부하 측정 요구사항 명세

현재 서버의 성능·안정성을 확인한다. 과거 순차 처리 서버와 비교하지 않는다. 검증 범위를 구현·실행했다. **최종 판정은 FAIL이며 TSan 경합 검증은 미완료다.**
구체 방법은 [설계 명세](final-validation-design.md), 기능 범위는 [리버스 프록시 요구사항](reverse-proxy-requirements.md)과 이전 단계 문서를 따른다.

## FR-054. 환경과 측정 경계

- 입력: 현재 Docker 실행 환경과 서버·부하 생성기·백엔드 설정.
- 동작: 같은 환경에서 비교 가능한 조건을 유지한다. CPU·RAM 제한과 실제 자원, 워커·큐·연결 상한, 시간 제한, 파일/본문 크기, 백엔드 수, 캐시·keep-alive 상태를 기록한다.
- 결과·완료 기준: 설정·버전·실행 명령으로 재현할 수 있다. 생성기나 백엔드가 병목인지 확인하며, 같은 호스트에서 자원을 나눠 쓰는 한계를 공개한다.

## FR-055. 정상 부하 측정

- 입력: 정적 파일 단독, 프록시 단독, 두 기능의 혼합 시나리오.
- 동작: 각 시나리오를 동시 요청 수 1·10·50·100으로 실행한다. 짧은 예비 실행 후 조건별 30초씩 3회 측정한다. 예비 실행은 정식 결과와 분리한다.
- 결과·완료 기준: 정상 요청의 상태·내용이 정확하고 예상 밖 실패가 0이어야 한다. 처리량·지연·반복 편차를 기록하되 최소 성능 수치는 요구하지 않는다.

## FR-056. 과부하와 지속 부하

- 입력: 동시 200의 별도 과부하와 10분 지속 부하.
- 동작: 200은 정상 부하와 구분한다. 모든 요청 성공을 요구하지 않고, 기존 상한·장애 정책과 부하 제거 후 회복을 확인한다. 10분 동안 지속적으로 요청해 장기 자원 변화와 오류를 확인한다.
- 결과·완료 기준: 크래시·잘못된 메모리 접근·누수가 없고 요청 내용이 훼손되지 않는다. 과부하의 오류를 정책·원인별로 설명하며 종료 뒤 정상 요청이 회복돼야 한다. 지속 부하의 구체 동시 수·혼합비는 DS-056의 AI안이다.

## FR-057. 장애와 회복 검증

- 입력: 실제 접속 시간 초과, 백엔드 장애·전송 중단, 클라이언트 단절, 종료 신호.
- 동작: 접속 거절과 접속 시간 초과를 구분해 재현한다. 기존 502·504, 최종 응답 시작 뒤 종료, 자동 재시도 없음, 복구·종료 유예를 검증한다.
- 결과·완료 기준: 선언한 장애 정책에 맞는 결과와 자원 정리를 확인하고, 장애 제거 뒤 정상 요청을 처리한다. 재현하지 못한 항목을 통과로 처리하지 않는다.

## FR-058. 응답·메모리·경합 검증

- 입력: 기존 회귀 검사와 정상/과부하/장애 요청.
- 동작: 상태·본문·길이·순서·요청 경계를 검증한다. sanitizer 검사는 성능 측정과 분리한다. ASan 등 메모리 검사를 수행하고 TSan도 다시 시도한다.
- 결과·완료 기준: 크래시·누수·invalid memory 접근이 없어야 한다. TSan이 기존 환경 오류로 시작하지 못하면 경합 검증 미완료로 기록한다. 다른 검사 통과로 대체하지 않는다.

## FR-059. 측정 지표와 판정

- 입력: 원시 측정 결과와 오류·자원 로그.
- 동작: RPS, 지연 p50·p95·p99, 오류 종류/수, CPU·RSS·FD·스레드 수의 전후 및 시간별 변화를 기록한다. 반복 3회의 편차도 표시한다.
- 결과·완료 기준: 정상 부하의 예상 밖 실패 0과 정확성, 과부하의 정책 준수·회복, 메모리 안전성을 판정한다. 최소 RPS나 지연 목표를 임의로 추가하지 않는다. 실패 항목은 수정 필요, 실행 불가는 미완료로 남긴다.

정책에 맞는 503·502·504라도 정상 시나리오에서 예상하지 않았다면 실패다. 원인 없는 부하 생성기 오류나 요청 deadline 초과를 단순히 과부하의 정상 결과로 분류하지 않는다.

## FR-060. 결과와 검증 한계 기록

- 입력: 환경·명령·원시 로그·반복 결과·실패 증거.
- 동작: 원시 자료와 요약표·보고서를 함께 남긴다. 포트폴리오용 정리는 실제 측정한 범위와 미검증·실패·환경 한계를 구분한다.
- 결과·완료 기준: 측정 경계와 조건을 추적할 수 있고, 미실행 기능·실험을 통과나 일반적인 성능 보장처럼 표현하지 않는다. 실패한 항목이 있으면 전체 검증 완료라고 보고하지 않는다.

## 사용자 결정과 설계 구분

현재 서버만 검증, 세 시나리오, 동시 1/10/50/100과 별도 200, 조건별 30초 3회·예비 실행, 10분 지속 부하, 정확성·실패·안전성 기준, 최소 성능 목표 없음은 사용자 결정이다.
워크로드 크기·혼합 비율·도구·수집 주기·장애 재현 방식·보고서 위치는 AI 설계안이다. 아래 문서의 수치는 측정 결과나 사용자가 개별 지정한 요구 수치가 아니다.
