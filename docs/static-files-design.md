## DS-015. 파일 루트 지정과 서버 시작

입력은 포트와 루트 인자다. 루트를 디렉터리로 열고 그 파일 디스크립터를 서버 종료까지 유지한다. 실패하면 오류를 출력하고 종료한다. 생략 시 기본 루트는 두지 않고 포트·루트 인자를 모두 필수로 받는 AI 설계 선택이다. 확인 기준은 올바른 루트로 시작하고 잘못된 루트로는 시작하지 않는 것이다.

## DS-016. URL 경로와 접근 제한

- 입력: 요청 원문 경로. 파일 탐색용 작업 공간에서 한 번만 퍼센트 디코딩한다. 쿼리는 사용하지 않고 `+`를 공백으로 바꾸지 않는다.
- 처리: 잘못된 `%` 표기와 디코딩 결과의 NUL은 400으로 처리하는 설계다. URL 루트 기준 상대 경로 성분을 순서대로 확인한다. `.`은 현재 위치, `..`는 부모로 처리하되 루트 위로 올라가려 하면 403이다.
- 결과·확인 기준: 루트 안의 `a/../b`는 `a`가 실제 접근 가능한 디렉터리일 때 허용한다. 일반·인코딩된 루트 탈출과 모든 심볼릭 링크는 거절한다.

단순 문자열 접두사 검사나 검사 후 절대 경로 재열기는 사용하지 않는다. 루트 디렉터리 FD에서 `openat()`·`O_NOFOLLOW`로 성분을 하나씩 열고 `fstat()`으로 확인한다. 디렉터리 FD 스택으로 부모 이동을 처리해 `a/../b`의 `a` 검사도 생략하지 않는다. 심볼릭 링크를 따라간 뒤 루트 안인지 확인하는 방식이 아니라, 링크 자체를 거절한다.
중간 디렉터리·최종 파일·추가로 찾는 `index.html`에도 같은 방식을 적용한다. 확인과 열기 사이에 경로가 교체돼도 링크를 따라 루트 밖 파일을 열지 않도록 한다.

## DS-017. 기본 페이지와 디렉터리 이동

- 입력: 안전하게 확인한 경로의 실제 파일 종류와 원문 URL.
- 처리: 디렉터리 요청에 슬래시가 없으면 301과 Location을 만든다. Location은 원문 URL 경로에 `/`를 붙이고, 원래 쿼리가 있으면 `?`와 함께 보존한다. 슬래시가 있으면 그 디렉터리에서 `index.html`을 안전하게 연다.
- 결과·확인 기준: `/docs?q=1`은 `/docs/?q=1`로 이동한다. index.html 없음은 404, 링크이면 403이다. 목록은 만들지 않는다.

Location에 디코딩된 문자를 직접 넣지 않는다. 헤더에 CR·LF·NUL이 들어가지 않는지도 확인한다. 301은 `Moved Permanently`, 빈 본문, `Content-Length: 0`, `Connection: close`를 사용하는 세부 설계다.

## DS-018. MIME 타입 결정

입력은 최종 파일 확장자다. 대소문자를 무시해 아래 표로 조회하고 모르면 기본 타입을 사용한다. 이는 AI의 기본 매핑이며 파일 내용을 변환하지 않는다. 확인 기준은 확장자별 타입과 원본 바이트 일치다.

| 확장자 | Content-Type |
| --- | --- |
| html, htm | text/html; charset=utf-8 |
| css | text/css; charset=utf-8 |
| js | text/javascript; charset=utf-8 |
| txt | text/plain; charset=utf-8 |
| png | image/png |
| jpg, jpeg | image/jpeg |
| gif | image/gif |
| svg | image/svg+xml |
| ico | image/vnd.microsoft.icon |
| 그 밖의 확장자·확장자 없음 | application/octet-stream |

텍스트 파일은 UTF-8로 준비하며 서버가 문자 인코딩을 변환하지 않는다.

## DS-019. 파일 응답 전송

- 입력: 안전하게 연 일반 파일 FD.
- 처리: `fstat()`의 크기로 Content-Length를 정하고 MIME과 `Connection: close`를 포함한 200 헤더를 보낸다. 파일 전체를 동적 메모리에 올리지 않고 고정 크기 버퍼로 읽어 전송한다. 각 송신은 남은 부분을 반복해 보낸다.
- 결과·확인 기준: 바이너리의 NUL을 포함해 파일 바이트를 그대로 보내며, 선언한 길이만큼 전송한다. 빈 파일은 본문 길이가 0이다.

첫 읽기는 헤더 전 수행해 즉시 발견한 읽기 실패에 500을 선택할 수 있게 한다. 파일이 전송 중 변경돼 조기 EOF·읽기 실패가 나면 연결을 닫는다. 파일이 커져도 처음 선언한 길이보다 더 보내지 않는다. 파일 변경 중 일관된 스냅샷 제공은 이번 기능이 아니다.

## DS-020. 오류 처리와 자원 정리

입력은 탐색·열기·읽기·송신 결과다. 응답 전에 확인한 오류는 아래 표로 처리하고 기존 상태명만 담는 텍스트 오류 응답을 재사용한다.

| 원인 | 결과 |
| --- | --- |
| 잘못된 퍼센트 표기·디코딩 NUL | 400 Bad Request |
| 파일·기본 페이지 없음, 디렉터리가 아닌 성분 | 404 Not Found |
| 권한 거절·루트 탈출·심볼릭 링크·일반 파일/디렉터리 외 종류 | 403 Forbidden |
| 그 밖의 파일 열기·읽기 등 내부 실패 | 500 Internal Server Error |

최종 후보는 `O_NOFOLLOW`와 `O_NONBLOCK`으로 열고 `fstat()`으로 종류를 확인해 FIFO 대기로 막히지 않게 한다. FIFO·장치·소켓 등은 전송하지 않는다. 가능하면 비정규 종류를 열기 전 확인도 하며, 최종 판정은 열린 FD 기준으로 한다.
헤더 전 파일 I/O 실패는 500으로 처리할 수 있지만, 헤더나 본문 일부를 이미 보낸 뒤에는 오류 응답을 덧붙이지 않고 닫는다. 송신 실패도 재귀 오류 응답 없이 정리한다.
요청마다 열린 파일·중간 디렉터리 FD와 작업 메모리를 성공·실패 모두 정리한다. 서버가 소유한 루트 FD는 요청 후에도 유지하고 서버 종료 시 회수한다. 응답에는 서버 절대 경로나 내부 오류 상세를 노출하지 않는다.

확인 기준은 [요구사항의 검증 계획](static-files-requirements.md#결정과-검증-계획)과 같다. 자원 정리 및 오류 후 다음 정상 요청까지 확인했다.

검증 결과: 파서 97개 검사, 응답 송신·읽기 실패 검사, 정적 응답·정리 2400회 검사와 sanitizer(주소·정의되지 않은 동작·누수) 검사 통과. 관리자 권한이 없는 Linux UID 65534에서 정적 파일 통합 테스트 15개가 통과했다. 서버 전체 부하 검사는 수행하지 않았다.

기존 오류 응답 TCP 회귀 12개도 통과했다. 정적 루트의 index.html을 기존 본문과 같은 바이트로 준비하고 HTML MIME으로 기대값을 갱신해 검사했다.
