기존 [정적 파일 설계](static-files-design.md)의 보안 정책과 응답 형식은 유지하면서 소켓 통신과 파일 작업을 분리한다.

## DS-021. 이벤트 루프와 작업 스레드 역할

- 입력: listen FD、클라이언트 FD, 작업 완료 알림.
- 처리: 단일 이벤트 루프가 level-triggered epoll과 non-blocking 소켓을 사용한다. recv·파싱·send는 루프만 수행한다. EAGAIN이면 다른 이벤트로 넘어가고, 보낼 데이터가 있을 때만 EPOLLOUT을 감시한다. 부분 송신 위치를 보관한다.
- 결과: worker는 파일 탐색·열기·읽기만 맡고 소켓을 읽거나 쓰거나 닫지 않는다. 완료 결과를 mutex로 보호한 완료 큐에 넣고 eventfd로 루프를 깨운다.
- 확인 기준: 느린 연결을 유지해도 다른 연결이 응답하며, 소켓 I/O가 루프를 무기한 막지 않는다. 파일 오류·301 결과도 루프가 응답한다.

연결 상태는 수신 → 파일 작업 대기 → 실행 → 송신 → 다음 읽기 대기 또는 정리로 구분한다. 한 연결에는 동시에 한 파일 작업만 허용한다. pthread 조건변수로 작업 스레드를 재우고, 공유 큐의 잠금 안에서 파일 I/O를 실행하지 않는다.

## DS-022. 실행 인자

- 입력: 포트·루트·workers·queue_limit·conn_limit 다섯 인자.
- 처리: 누락, 숫자 뒤 잔여 문자, 0·음수, 표현 범위 초과와 할당 크기 계산 넘침을 거절한다. 포트는 기존 범위를 유지한다. 지정 자원이나 스레드를 모두 만들지 못하면 이미 만든 자원을 정리하고 시작을 중단한다.
- 결과·확인 기준: 예시 4·64·100을 기본값으로 넣지 않고 인자대로 동작한다. 부분 초기화 실패도 누수 없이 종료한다.

## DS-023. 작업 대기열과 포화 처리

- 입력: 첫 파일 작업과 후속 조각 읽기 작업.
- 처리: 대기열은 상한 있는 FIFO로 관리하며, worker가 작업을 꺼낼 때 대기 개수를 줄인다. 처음 제출할 때 가득 차면 503을 선택한다. 후속 읽기는 연결별 재시도 대기 목록으로 이동한다.
- 결과·확인 기준: 완료 알림이나 큐 공간 알림을 받으면 오래 기다린 후속 작업부터 빈자리에 넣는다. 한 번 재시도하다 다시 포화면 멈춘다. 폴링 반복이나 이벤트 루프에서 조건변수 대기를 하지 않는다.

재시도 목록은 작업 큐 항목 수에 포함하지 않지만 유지 연결 수로 제한된다. 정상 대기열과 재시도 목록 모두 순서를 보존하고, 새 요청의 연속 도착으로 기존 후속 읽기가 굶지 않게 한다. 대기 시간은 목록을 옮겨도 원래 시작 시각을 유지한다.

## DS-024. 파일 조각 전송

- 입력: 안전하게 연 파일과 남은 전송 길이.
- 처리: 기존 유한 버퍼 방식에 맞춰 조각 크기는 8192바이트로 선택한다. worker가 최대 한 조각을 읽고 소유권을 완료 결과로 넘긴다. 루프가 완전히 송신한 뒤에만 다음 읽기를 요청한다. 이 수치는 사용자 지정값이 아니다.
- 결과·확인 기준: 연결마다 전송 대기 파일 조각은 최대 하나이며 prefetch·전체 파일 적재가 없다. 선언한 Content-Length보다 더 보내지 않는다. 조기 EOF·읽기 실패는 기존 응답 시작 여부에 맞춰 처리한다.

첫 파일 탐색·열기·메타정보 확인·첫 읽기는 첫 작업에 묶을 수 있다. 헤더 전 오류는 기존 상태 응답으로, 헤더 이후 오류는 연결 종료로 처리한다. 큐 슬롯은 각 조각의 작업 단위로 사용한다.

## DS-025. 유지 연결 수 제한

- 입력: 열린 클라이언트 연결 수와 CLI 상한.
- 처리: 상한이면 listen FD를 epoll 감시에서 제외하고, 연결 객체 정리로 슬롯이 나면 다시 등록한다. 실행 중 작업 때문에 소켓을 먼저 닫아도 객체는 완료까지 슬롯을 차지한다. 한 번의 수락 반복에서도 매번 상한을 확인한다. 종료 중에는 재등록하지 않는다.
- 결과·확인 기준: 수신·작업 대기·실행·송신 상태를 모두 세어 제한한다. 커널 backlog 수치나 HTTP 응답 보장은 이 상한과 구분한다.

파일 작업에도 FD가 필요하므로 프로세스 FD 한도와 필수 자원 확보 가능성을 시작 시 확인한다. 실행 중 EMFILE·ENFILE이면 오류를 기록하고 수락 감시를 잠시 멈춰 자원이 회수되거나 유한 대기 후 재시도한다. 계속 깨어나는 무한 재시도를 하지 않으며 503을 약속하지 않는다.

## DS-026. 시간 제한

- 입력: CLOCK_MONOTONIC 시각과 연결 상태 전이.
- 처리: 수신 마감, 작업 대기 마감, 송신 무진행 마감을 별도로 기록한다. epoll_wait의 대기 시간은 가장 가까운 마감까지로 잡고 이벤트 처리 전후에도 만료를 확인한다.
- 결과·확인 기준: EINTR·EAGAIN·작업 재등록이 기존 마감을 연장하지 않는다. 타임아웃 처리는 해당 상태에서 한 번만 실행한다.

수신 마감은 accept 직후 한 번 정한다. 각 파일 작업의 대기 마감은 처음 기다릴 때 정하며 worker가 잠금 안에서 맡는 시점에 대기를 끝낸다. 기한이 지난 작업은 새로 실행하지 않도록 제출·인수 시 함께 확인한다. 실제 파일 I/O에는 별도 실행 시간 제한을 추가하지 않는다.

송신 타이머는 보낼 데이터가 준비되면 시작하고, send가 양수 바이트를 반환했을 때만 갱신한다. 파일 작업을 기다리거나 실행하는 동안에는 송신 타이머를 적용하지 않는다. 다음 데이터가 준비되면 새 송신 구간이 시작된다.
대기 시간 초과 시 전송 바이트 수가 0이면 503을 준비한다. 이미 한 바이트라도 보냈다면 연결만 닫는다. 408·503을 준비하면 이전 수신·작업 대기 마감을 끝내고 응답 송신 무진행 제한만 적용해 오류 응답을 반복 생성하지 않는다.

## DS-027. 종료 유예

- 입력: SIGINT·SIGTERM.
- 처리: 작업 스레드는 SIGINT·SIGTERM을 차단해 이벤트 루프 스레드만 신호를 받는다. 시그널 처리기는 종료 알림만 전달하고 잠금·메모리 정리·스레드 합류를 하지 않는다. 루프가 알림을 받아 수락 감시를 중단하고 최초 종료 시점부터 10초 기한을 정한다. 기존 요청에는 필요한 후속 작업을 계속 제공한다.
- 결과·확인 기준: 요청과 작업이 모두 끝나면 worker를 깨워 종료시키고 join 후 정상 정리한다. 기한이 먼저 끝나면 남은 클라이언트 소켓을 루프가 닫고 프로세스를 종료한다.

파일 I/O 중인 스레드가 10초 안에 돌아온다는 보장은 없다. 그 스레드를 무리하게 pthread_cancel하거나 그 FD·메모리를 다른 스레드에서 해제하지 않는다. 기한 종료 경로는 무기한 join 대신 프로세스 전체 종료를 사용해 OS가 남은 스레드·FD·메모리를 회수하게 하는 설계다. 정상 완료 경로에서만 모든 worker의 정지를 확인한 뒤 공유 큐와 루트 FD를 해제한다.

## DS-028. 연결별 자원과 실패 처리

- 입력: 연결 종료·작업 취소·늦게 도착한 완료 결과.
- 처리: 소켓과 연결 상태는 루프가 소유한다. 작업에는 연결 식별자와 세대 번호를 붙이고, 정수 FD만으로 요청을 식별하지 않는다. 완료 결과의 세대가 다르거나 이미 닫혔으면 송신하지 않고 결과만 정리한다.
- 결과·확인 기준: 재사용된 소켓에 이전 결과가 전달되지 않고, worker 실행 중 자원이 해제되지 않는다.

요청 구조체는 내부 포인터가 자기 버퍼를 가리키므로 연결마다 고정 위치에 유지하고 값 복사·realloc 이동하지 않는다. 큐에는 구조체 자체가 아닌 안정된 작업 참조를 넣는다.
연결 단절 시 아직 대기 중인 작업은 잠금 아래 제거·취소한다. 실행 중이면 소켓만 닫고 작업이 참조하는 요청·파일·버퍼의 수명은 완료까지 유지한다. 파일 FD는 실행 worker가 사용하는 동안 다른 스레드에서 닫지 않는다. 완료 시 소유권을 명시적으로 넘기고 한 곳에서만 정리한다. 루트 FD는 모든 worker가 끝나거나 프로세스가 종료될 때까지 유지한다.
완료 큐와 알림 경로는 이미 맡긴 작업의 결과를 잃지 않도록 필요한 슬롯을 미리 확보한다. 연결별 한 작업 제한과 스레드 수를 기준으로 대기·실행·완료 결과가 무제한 쌓이지 않게 한다. 요청 실패는 다른 연결에 전파하지 않고, 응답 시작 뒤 새 오류 응답을 덧붙이지 않는다.

## 검증 계획과 상태

`make all test sanitize`를 통과했다. 파서 97개, 정적 파일 2400개, 응답·수신 검사와 동시 상태 검사를 포함한다.
동시 상태 검사는 신규 503, 후속 읽기 재시도·FIFO·기한 보존, 전송 전후 대기 시간 초과, 실행 중 객체 수명을 확인한다.
기존 오류 TCP 12개, 정적 파일 TCP 15개와 동시 TCP 10개를 통과했다. 동시 TCP는 느린 수신·송신 병행, 큐 포화, 작업 대기 시간 초과와 실행 시간 제외, 연결 상한·재개, 단절·FD 재사용, 종료 조기 완료와 10초 강제 종료를 확인했다.
전체 서버 ASan·UBSan·누수 검사는 병렬 요청·단절·큐 포화·정상 종료 4개 시나리오를 통과했다. 단위 검사도 ASan·UBSan·누수 검사를 통과했다.
TSan은 `unexpected memory mapping` 런타임 오류로 검증을 완료하지 못했다. 강제 종료 경로의 OS 자원 회수는 정상 종료 누수 검사와 구분한다. 처리량 부하 측정은 실행하지 않았다.
테스트 지연은 `tests/slow_file.c`를 별도로 링크한 빌드에만 넣으며 운영 CLI에는 추가하지 않는다.
