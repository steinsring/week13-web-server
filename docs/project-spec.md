# 1단계 요구사항 명세

이 문서는 **무엇을 구현하고, 어떤 결과가 나오면 완료인지** 정한다.
구현 방법은 [설계 명세](design-spec.md)에 정리한다.

다음 단계는 [HTTP 요청 파싱 요구사항 명세(초안)](http-parser-requirements.md)에서 다룬다.

## 목표

C로 서버를 실행하고, HTTP 요청을 받으면 `hello world`를 응답한다.
이번 단계는 전체 과제 중 가장 기본적인 요청·응답 흐름만 구현한다.

## 기술 사용 조건

아래 조건은 처음 제공된 과제의 기술 제한이다. 이번 1단계에도 적용한다.

### 반드시 사용할 것

- 구현 언어는 C를 사용한다.
- TCP 연결과 데이터 송수신은 POSIX 소켓 API로 직접 구현한다.
- Windows에서는 WSL2 + Ubuntu, Docker 또는 클라우드의 Linux 환경에서 개발한다. 이 프로젝트는 Docker의 Linux 컨테이너에서 빌드하고 실행한다.
- 빌드 방법으로 `Makefile` 또는 `CMakeLists.txt`를 제공한다. 이번 구현은 `Makefile`을 사용한다.

### 사용해도 되는 것

- 표준 C 라이브러리와 POSIX API를 사용한다.
- 예: `<sys/socket.h>`, `<netinet/in.h>`, `<unistd.h>`, `<pthread.h>` 등. 허용된 모든 API를 반드시 사용할 필요는 없다.
- `curl`과 브라우저는 서버 동작을 확인하는 클라이언트로 사용할 수 있다.

### 사용하면 안 되는 것

- 외부 HTTP 라이브러리나 프레임워크에 요청 파싱, 응답 생성, 서버 동작을 맡기지 않는다.
- `libevent`, `libuv`, `nginx`, Apache, `mongoose` 같은 완성된 HTTP 서버·이벤트 루프 라이브러리 또는 제품으로 구현을 대체하지 않는다.
- Windows 전용 소켓 API인 Winsock으로 POSIX 소켓 구현을 대체하지 않는다.

### 전체 과제에서 이후에 적용할 조건

- 최종 실행 방법은 포트 번호, 정적 파일 루트, Reverse Proxy 선택 시 라우팅 규칙을 CLI 인자 또는 설정 파일로 받도록 한다. 이번 단계의 구체적인 포트 지정 방법은 미정이다.
- 전체 과제는 Proxy 또는 Reverse Proxy 중 최소 하나를 구현해야 한다. 이번 1단계에서는 제외한다.
- 여러 OS에서 실행할 때는 POSIX 표준 범위를 사용하거나 `#ifdef`로 플랫폼 차이를 처리한다.

이번 단계에서 제외한 기능은 사용 금지 기술이 아니라, 이후 단계에서 구현할 범위다.

## 기능 요구사항

### FR-001. 서버 시작과 연결 수락

- 서버를 실행하면 지정된 포트에서 클라이언트 연결을 기다린다.
- 연결이 들어오면 수락하고 요청을 받는다.
- 완료 조건: 클라이언트가 서버에 연결할 수 있다.

### FR-002. HTTP 요청 수신

- 브라우저 또는 `curl`이 보낸 HTTP 요청을 받는다.
- 이번 단계의 확인 대상은 본문 없는 GET 요청이다.
- 요청 헤더를 모두 받은 뒤 응답한다.
- 완료 조건: 요청 헤더를 모두 받은 뒤 응답 단계로 넘어간다.

### FR-003. HTTP 응답 전송

- 정상 요청에 HTTP 성공 응답을 보낸다.
- 클라이언트가 본문을 일반 텍스트로 읽을 수 있어야 한다.
- 본문은 소문자 `hello world`만 보낸다. 끝에 줄바꿈은 붙이지 않는다.
- 완료 조건: 클라이언트가 정상 응답과 정확히 11바이트의 본문을 받는다.

### FR-004. 연결 종료와 다음 요청 대기

- 응답을 모두 보내면 해당 클라이언트 연결을 닫는다.
- 서버는 종료하지 않고 다음 연결을 기다린다.
- 요청은 한 번에 하나씩 순서대로 처리한다.
- 완료 조건: 서버를 재실행하지 않아도 새 연결로 반복 요청할 수 있다.

## 이번 단계에서 제외하는 기능

정적 파일 서빙, POST 본문 처리, 동적 처리, 동시 요청 처리, 프록시, 연결 유지(keep-alive), 부하 테스트는 구현하지 않는다.

## 전체 완료 조건

- Docker의 Linux 컨테이너에서 C 서버를 빌드하고 실행할 수 있다.
- 브라우저 또는 `curl`로 요청하면 `hello world`를 받는다.
- 같은 서버에 반복 요청해도 매번 동일한 응답을 받는다.
- 각 응답 후 해당 연결은 닫히고, 서버는 다음 연결을 기다린다.

이 조건은 1단계의 완료 기준이며, 전체 과제의 완료 기준은 아니다.

## 최소 구현에서 선택한 기본값

아래는 구현 과정에서 선택한 값이며, 과제에서 지정한 수치는 아니다.

- 포트: 기본 8080, 실행 인자로 변경한다.
- 빌드: `Makefile`을 사용한다.
- 종료: 직접 실행은 Ctrl+C, Docker 실행은 `docker stop`을 사용한다.
- 요청 헤더 크기: 최대 8192바이트다. 초과 또는 불완전한 상태에서 연결이 끊기면 해당 연결을 닫는다.
- 서버 초기화 실패 시 오류를 출력하고 종료한다. 클라이언트 송신 실패 시 연결을 닫고 다음 연결을 기다린다.
- 요청 형식 검증, 오류 HTTP 응답, 수신 타임아웃은 이후 단계에서 정한다.
